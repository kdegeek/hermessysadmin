**Skill content requirements:**
- `fleet-health-check`:
  1. `fleet_inventory`.
  2. Rank problems: offline > 7 d, low disk, patch age, pending reboots, Defender off, BitLocker off, RDP without NLA.
  3. For the top issues, `catalog_search` for a matching entry and propose the fix with `catalog_run`. Writes need approval; never batch more than 10 machines without saying it will be high-risk.
  4. End with a short table.
- `endpoint-triage` (a user says their PC is slow or broken):
  1. `fleet_device`.
  2. `catalog_run` `endpoint.top_processes`, `endpoint.recent_errors`, `endpoint.pending_reboot`, `endpoint.disk_usage`, `endpoint.stopped_auto_services`.
  3. Diagnose.
  4. Suggest fixes as catalog ids (`maint.clear_temp`, `maint.restart_service`, `remote.restart_computer`), each requiring approval.
- `remote-assist`:
  1. `remote_sessions` for the machine.
  2. If the user is present, offer `remote_assist_command` (consent-based) or shadow with consent.
  3. If nobody is logged on, RDP via `rdp_connect_file`.
  4. Run `remote_access_check` first and propose the `remote.*` fix entries for failing checks.
  5. Never use no-consent shadow unless the admin explicitly asks; it is high-risk.

**`verify_live.py` additions** (all read-only; writes use previews):
- `fleet_inventory`; then pick the first online workstation `ws` from the result.
- `fleet_device {computer: ws}`, `remote_sessions {computers: [ws]}`, `remote_access_check {computer: ws}`, `fleet_history {days: 30}`, `catalog_module_status`, `monitoring_status`.
- Every R catalog entry:
  - `target: endpoint` entries get `{computers: [ws]}`;
  - `target: dc` entries get `{}`;
  - required params get safe sample values from a dict in the script: `endpoint.installed_software` → none; `network.test_port` → `{Target: <dc>, Port: 389}`; `events.search` → `{Log: "System", Id: 6005}`; `dns.stale_records` → `{Zone: <domain>}`; `dhcp.leases_for_host` → `{Name: ws short name}`; `files.*` → `{Path: "\\\\<domain>\\SYSVOL"}` and `{Account: "Domain Users"}` where needed.
  - Gallery entries whose module is not installed are reported as `SKIP NotInstalled`. They are not failures. Don't install modules during verification; installing is an H op the user approves.
- Previews: `cat.remote.set_nla {computers:[ws], Required:true}`, `cat.maint.gpupdate {computers:[ws]}`, `cat.remote.restart_computer {computers:[ws], Reason:"verify"}`, `catalog_module_install {name:"NTFSSecurity"}`, `monitoring_enable {deliver:"origin"}`. Previews never change anything.
- The summary line counts OK / SKIP / ERR separately. The exit code is non-zero only on ERR.
